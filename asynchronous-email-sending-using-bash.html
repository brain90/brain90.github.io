Async Email Using PHP &amp; Bash

2020-03-30 · Kehidupan

Problem #1: An apps need to send email once a save event executed. Apps & Send mail api made with PHP. [ solved ].

Problem #2: Now the apps need to broadcast email. At least 20 receiver a time. Simulteneously. Save event now blocking ( > 1 minutes ) until whole email process finished. Solve the problem.

Solution:
With only bash and curl we can solve this problem easily. First, after save event completed create pid file at pid_directory. I use row_id as event_id. This pid used as queue list. Put the script below into crontab to run it as daemon. Set to run every two minutes. We assume all email processed in less than two minutes.

Every two minutes the daemon will check the pid directory. If the directory contains pid files, the daemon will process it one by one in the background. Hence email process now can run simultaneously. And the blocking gone automatically.

#!/bin/bash
#set -x
api_url='http://secret-domain.com/api/email_quote/'
pid_directory='/home/user/broadcast_queue/'
send_mail(){
  pid="$1.process"
  pid_path=$pid_directory"$pid"
  mv $pid_directory"$1" $pid_path
  curl $api_url"$1" > $pid_path
  if grep -Fxq "success" $pid_path
  then
    rm $pid_path
    echo $(date +"%Y%m%d %H:%M")" - $1 created" 2>&1 >> $pid_directory"mail.log"
  else
    echo $(date +"%Y%m%d %H:%M")" - $1 error" 2>&1 >> $pid_directory"mail.log"
  fi
}
# check if there is available queue to process 
quote_list=$(ls -1 -I "*.process" -I "*.log" $pid_directory)
if [ -z "$quote_list" ]
then
  echo "nothing to process"
  exit 0
fi
for filename in $quote_list; do
  # make asynchronous by put it into background
  send_mail $(basename $filename) &
done

This way are the primitive one. The system are not critical. Broadcast failure are negligible. I just create it to solve the problem as fast as possible. You should move the queue into database or modify it with your needs.
